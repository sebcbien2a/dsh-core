ARCHITECTURE AGENTIQUE AUTONOME

Spécification Technique & Blueprint Systémique Multi-Boucles Local

MASTER BLUEPRINT V2.3 (EXHAUSTIF & INTÉGRAL - 10 SECTIONS)
Résumé Exécutif : Ce document régit l'installation globale du système IA autonome local (dsh-core). Il orchestre les modèles spécialisés (Qwen Coder 14B/32B, DeepSeek 32B/R1, Mistral, Llama Vision, Flux/ComfyUI, Llama 3.2 3B) via le harnais dsh, gère la mémoire multi-niveaux et persistante (Mem0 + AnythingLLM + cold_storage), intègre les sous-agents d'exécution (dont le sous-agent de recherche web autonome ResearchAgent), gère le registre dynamique des compétences (Auto-écriture et téléchargement de Skills), connecte les sources de données (Google Drive Multi-Comptes, OneDrive, VS Code, n8n) et assure l'observabilité et le contrôle qualité en temps réel (Langfuse + React Flow + LLM-as-a-Judge).

1. Cartographie des 3 Boucles Agentiques & Cockpits UI

1. Cockpit & UI

  • VS Code / CLI : Dev direct & contrôle dsh-core.
  • AnythingLLM : Chat, RAG local & mémoire froide.

4. Boucle Jaune

  • Mem0 : Faits clés & préférences.
  • Llama 3.2 (3B) : Résumé & compression contextuelle.
  • AnythingLLM : Vector DB sur cold_storage/.

2. Schéma Système Global, Flux d'Exécution & Gestion des Skills

2.1 Schéma Visuel de l'Architecture (Photo 2)

Figure 2.1 — Schéma synoptique de la boucle agentique éphémère (RAM), de la boucle d'outils, de la mémoire procédurale (SKILL.md), du système de compression et de la porte de contrôle LLM Ops.

Décomposition technique du flux d'exécution :

  • Enveloppe Harnais (Harness Scope) : Le moteur dsh-core englobe la totalité de la session. Il maintient une étanchéité stricte entre l'espace d'exécution temporaire et le stockage froid d'archivage.
  • Boucle Agentique Éphémère (RAM) : Le contexte est assemblé à partir de la demande utilisateur, de l'historique récent et du prompt système, puis enrichi dynamiquement par :
    • SKILL.md (Mémoire procédurale / instructions de compétences et règles d'action).
    • DB Vectorielle (Mémoire sémantique / faits persistants récupérés via RAG top-k).
    • DB / SQL (Mémoire épisodique / événements récents et historique de conversations).
  • Boucle d'Outils (Tool Loop) : L'Agent IA sollicite des outils dédiés (ex : ResearchAgent, workflows n8n, CRM, scripts). Les retours repassent par une couche de sécurité (Guardrails) avant réponse à l'utilisateur.
  • Système de Compression de la Mémoire : Au franchissement d'un seuil de $N$ messages, l'agent ultra-léger Llama 3.2 (3B) extrait les faits essentiels et les enregistre dans la mémoire sémantique durable.
  • Module LLM Ops & Porte de Qualité (LLM Ops Gate) : Chaque exécution génère une trace complète ($1\text{ Run} = 1\text{ Trace}$) envoyée vers Langfuse. Le composant LLM-as-a-Judge évalue la conformité du résultat.

2.2 Moteur Dynamique des Skills (Auto-écriture & Téléchargement/Import)

Pillar du Système Agentique : Le Registre de Compétences (`SKILL.md` & `memory/skills/`)
Le système ne se contente pas de répondre à des requêtes ; il apprend et étend ses capacités de manière autonome selon deux mécanismes complémentaires :
  • 1. Auto-écriture & Apprentissage Autonome (Auto-Skills) :
    • Lorsqu'un agent réussit une tâche complexe ou résout un bug via la boucle d'escalade, le composant LLM-as-a-Judge (Boucle Verte) extrait la séquence d'actions gagnante.
    • L'agent rédige ou enrichit automatiquement une fiche de compétence au format Markdown dans A:\dsh-core\memory\skills\NAME.md et met à jour le registre central SKILL.md.
    • Lors des futures sessions, ce skill est injecté en mémoire procédurale (RAM) dès qu'une tâche similaire est détectée.
  • 2. Téléchargement, Importation & Veille de Skills Externe :
    • Importation Git/MCP : Le serveur Git MCP permet à l'agent de cloner ou de synchroniser directement des répertoires de compétences/prompts communautaires (ex: GitHub, LangChain Hub, registres MCP).
    • Recherche & Scraping via `ResearchAgent` : L'agent de recherche web peut télécharger des documentations API, des guides techniques ou des workflows n8n, les synthétiser via Llama 3.2 (3B) et les convertir en fiches de compétences exécutables.

4. Logique de Routage en Cascade & Contrôle Utilisateur

A. Routage Automatique par Escalade (Fallbacks) : Le harnais dsh applique un principe strict d'économie de ressources VRAM :

  • Démarrage ultra-rapide : La tâche est d'abord confiée au modèle le plus léger (ex : Qwen 14B).
  • Détection d'échec (Boucle Verte) : Le composant LLM-as-a-Judge vérifie le résultat (syntaxe, critères respectés, format JSON).
  • Escalade automatique : En cas d'erreur ou de rejet, le harnais réinjecte le journal d'erreur et passe la tâche au modèle supérieur (32B ou DeepSeek R1).
  • Dernier recours : Si le 32B local échoue, bascule transparente vers l'API OpenRouter (Claude / GPT-4o).

B. Sélection Manuelle (User Override) : L'utilisateur conserve la priorité absolue à tout moment :

  • Sélecteur UI : Dans VS Code (Continue) ou AnythingLLM, un champ permet d'imposer un modèle spécifique pour une session.
  • Profils par Projet : Possibilité de définir des règles strictes (ex : "Projet X = 100% Qwen 14B pour préserver la VRAM GPU").
  • Déclenchement direct d'outils : Dire "Recherche sur le web..." active directement ResearchAgent sans passer par l'escalade textuelle.

5. Connecteurs Cloud & Intégration Documentaire

Afin de permettre à l'agent de retrouver et d'analyser tous tes documents sans import manuel :

  • Google Drive MCP (Multi-comptes) : Branchement simultané des comptes professionnels et personnels via l'API Google Workspace. L'agent peut rechercher des fichiers par nom, contenu, date ou dossier.
  • OneDrive MCP : Connecteur Microsoft Graph permettant l'exploration des dossiers Cloud OneDrive, la lecture de tableurs Excel, et la synchronisation locale.
  • RAG Hybride (AnythingLLM) : Les documents et archives générés dans A:\dsh-core\memory\cold_storage\ sont indexés automatiquement dans la base vectorielle locale pour des recherches sémantiques instantanées.

6. Observabilité Visuelle en Temps Réel (Écran Secondary Dashboard)

Pour sortir de l'effet "boîte noire", l'architecture intègre un double système de suivi en direct :

  • A. Langfuse (Docker) — Traçabilité & Logs Fine :
    • Arbre d'exécution (Traces) : Visualisation exacte de chaque appel de fonction et de chaque sous-agent.
    • Statistiques en direct : Nombre de tokens consommés, modèle sollicité (14B vs 32B), latence en millisecondes.
    • Inspecteur MCP : Visualisation des données brutes envoyées/reçues depuis Google Drive, n8n ou le système de fichiers.
  • B. Schéma Animé (React Flow / Langflow) :
    • Surbrillance Dynamique : Chaque fois qu'une boucle s'active, la case correspondante sur le schéma s'allume (ex : Jaune quand Mem0 écrit, Orange quand ResearchAgent ou n8n s'exécutent).
    • Impulsions Lumineuses : Des flux animés le long des flèches montrent le déplacement des données en temps réel.
    • Alerte d'Échec : Clignotement rouge immédiat lors d'un rejet par la Boucle Verte suivi de l'animation d'escalade vers le modèle 32B.

7. Spécifications Techniques des Composants Clés

  • DeepSeek Harnais (dsh-core) : Moteur d'orchestration central situé dans A:\dsh-core\, pilotable via CLI, n8n ou AnythingLLM. Il découpe le prompt en plan d'action, choisit le modèle et émet des événements WebSocket en direct vers Langfuse.
  • Sous-Agent `ResearchAgent` (agents/research_agent.py) : Script Python de collecte web autonome. Il effectue les requêtes réseau, extrait le texte brut, le fait structurer en JSON par llama3.2:3b et l'archive en mémoire froide.
  • Registre de Compétences (`SKILL.md`) : Répertoire dynamique stockant les procédures réutilisables créées automatiquement par la Boucle Verte ou importées depuis le web/Git.
  • Mem0 + Llama 3.2 3B (Moteur de Mémoire Persistante) : Évite la saturation du contexte. Régulièrement, le sous-agent Llama 3.2 3B extrait les faits durables et les stocke dans la base sémantique.
  • Moteur de Workflows n8n & Serveurs MCP : Le bras armé du système pour les actions dans le monde réel (scraping, envoi de mails, gestion de factures, automatismes).

9. Exemples Concrets d'Exécution du Système

Scénario 1 : Recherche Web Autonome & Téléchargement d'un Skill

  • 1. Réception : L'utilisateur lance python dsh_harness.py --research "Nouveautés Ollama 2026".
  • 2. Appel Outil (Boucle Orange) : ResearchAgent télécharge la documentation et extrait une nouvelle procédure de configuration.
  • 3. Auto-Skills (Boucle Verte) : Le système enregistre automatiquement cette procédure dans memory/skills/ollama_config.md.
  • 4. Mémoire (Boucle Jaune) : La synthèse JSON est sauvegardée dans memory/cold_storage/research_20260919.json et indexée dans AnythingLLM.

Scénario 2 : Recherche Immobilière Multi-Critères

Injonction : "Trouve-moi la liste des appartements T3/T4 à vendre sur [Ville] < 250k€ avec terrasse, mets-les dans un tableau propre et fais une synthèse."

  • 1. Réception Prompt : Le harnais dsh attribue la tâche initiale à Qwen 14B (rapide).
  • 2. Appel Outil (Boucle Orange) : Qwen 14B déclenche le workflow n8n de scraping des annonces et interroge Google Drive / OneDrive.
  • 3. Traitement & Contrôle (Boucle Verte) : Si Qwen 14B rate un critère, le Judge rejette le résultat et bascule automatiquement vers Qwen 32B / DeepSeek R1.
  • 4. Mémoire (Boucle Jaune) : Mem0 extrait tes critères (T3/T4, Ville, < 250k€) pour s'en souvenir lors de tes prochaines sessions.
  • 5. Observabilité (Écran 2) : Le schéma React Flow s'allume en direct et Langfuse enregistre le coût de la requête.

10. Principes de Maintenance & Évolutivité

  • Remplacement d'un Modèle : Pour intégrer un nouveau modèle (ex : Qwen 3 ou Llama 4), il suffit de modifier son nom dans le fichier de config du harnais dsh. Aucun workflow n8n ou serveur MCP n'a besoin d'être réécrit.
  • Génération & Maintenance des Skills : Le fichier SKILL.md et le dossier memory/skills/ restent persistants. L'utilisateur ou l'agent peut y ajouter, modifier ou supprimer des fiches de compétences sans recompiler le système.
  • Ajout de Comptes Cloud : Il suffit de rajouter un jeton d'accès OAuth dans le serveur MCP Google Drive / OneDrive pour étendre instantanément le périmètre de recherche de l'agent.
  • Persistance de la Mémoire : Les répertoires de mémoire (cold_storage), AnythingLLM, les bases Mem0 et les fichiers SKILL.md sont stockés en local sur le disque et survivent à toutes les mises à jour logicielles.
