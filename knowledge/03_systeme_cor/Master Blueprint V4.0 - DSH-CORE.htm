MASTER BLUEPRINT V4.0 - ARCHITECTURE SYSTÉMIQUE DSH-CORE

Résumé Exécutif :
Ce document de spécification régit l'installation globale du système IA autonome local (dsh-core) déployé sur l'environnement A:\dsh-core\ via Python 3.11, optimisé pour une RTX 4070 et 32 Go de RAM. Conçu pour automatiser l'activité de distribution (Corse et Val de Loire), le système abandonne la logique des agents isolés au profit d'un orchestrateur déterministe unique (LangGraph). Il unifie le contexte documentaire via un RAG universel (Qdrant), résout la logique comptable complexe (Neo4j), et s'interface avec le monde réel via une boîte à outils standardisée (MCP Hub). La puissance de cette version réside dans sa boucle d'auto-apprentissage (Teacher-Student) et l'interconnexion de ses clients aveugles partageant la même mémoire.

PAGE 2 : STRATE 1 & 5 - LE CONTEXTE RAG UNIVERSEL ET LA MÉMOIRE

La fragmentation de la mémoire est définitivement éliminée. Historiquement, chaque application possédait ses propres données. Désormais, le RAG (Retrieval-Augmented Generation) est centralisé.

1. Le Rôle Central d'AnythingLLM

AnythingLLM est configuré comme un client strict. Il est débarrassé de sa base vectorielle interne. Il interroge exclusivement le document_bus (LlamaIndex) hébergé sur Qdrant. Lorsqu'une requête est formulée dans l'interface (ex: "Quelles sont les conditions de franco de port pour Paintcar ?"), l'outil puise dans la même base de connaissances que l'agent comptable exécutant des tâches en arrière-plan.

2. La Triforce de la Mémoire (Sémantique et Relationnelle)

Le système s'appuie sur deux moteurs de base de données fonctionnant en symbiose totale :

  • Qdrant (Port 6333 - La Compréhension Sémantique) : Base vectorielle structurée en 3 collections :
    • mem0_memories : Stocke les faits épisodiques, les préférences de l'utilisateur et les règles métiers persistantes extraites par Qwen 9B.
    • document_bus : Indexation intégrale du texte brut de tous les PDF (factures, devis, correspondances) via LlamaIndex.
    • skills_catalog : Le répertoire centralisé contenant les directives d'extraction sur-mesure pour chaque fournisseur.
  • Neo4j (Port 7474 - Le Raisonnement Mathématique et Comptable) : Base de données orientée graphe. Elle ne stocke pas le texte des factures, mais cartographie visuellement les relations comptables strictes (Nœud Facture ↔ Nœud Avoir ↔ Nœud Paiement LCR). C'est le moteur décisionnel du lettrage.

PAGE 3 : STRATE 3 & 4 - LE PIPELINE DE TRAITEMENT ET LA CASCADE AGENTIQUE

Le traitement des documents et l'exécution des tâches répondent à un flux rigide, géré par le Cerveau Central (LangGraph) qui attribue le travail selon une hiérarchie stricte d'agents.

1. Pipeline Documentaire (Usine de Triage)

  1. Triage Visuel : Si le flux entrant est une image (ticket de caisse thermique, note de frais scannée), l'orchestrateur route vers Qwen2.5-VL (7B) pour une extraction spatiale directe.
  2. Triage PDF : Si le flux est un document comptable standard, Surya OCR procède à l'extraction massive du texte brut.
  3. Structuration (Tier Rapide) : Qwen 9B prend le relais. Il applique un schéma Pydantic strict, valide l'arithmétique du document (Total HT + TVA = TTC) et convertit les données en JSON propre.

2. Le Hub MCP (La Boîte à Outils)

L'intelligence artificielle n'est plus enfermée dans une boîte de texte. Via le Model Context Protocol, elle interagit avec l'écosystème du distributeur :

  • Action OS & Fichiers : Lecture/écriture sur A:\dsh-core\, archivage des PDF traités et manipulation du dépôt Git.
  • Actions Bureautiques (Office) : Capacité autonome à générer, éditer et pré-remplir des tableurs Excel (.xlsx) pour le réassort.
  • Connecteurs Distants : Accès API à Google Drive/OneDrive et déclenchement de webhooks sur n8n (ex: envoi d'emails récapitulatifs post-lettrage).

PAGE 4 : LA BOUCLE D'AUTO-AMÉLIORATION (TEACHER-STUDENT)

Il s'agit du cœur névralgique de l'architecture anti-fragile. Lorsqu'un document provenant d'un fournisseur inconnu provoque un échec mathématique ou de formatage, le système ne plante pas ; il apprend à écrire ses propres règles.

[ NOUVELLE FACTURE INCONNUE ] ──► ÉCHEC D'EXTRACTION (QWEN 9B) │ ▼ ┌───────────────────────────┐ │ TIER EXPERT (Qwen 27B) │ │ Tente de résoudre local. │ └────────────┬──────────────┘ │ (Si échec persistant) ▼ ┌───────────────────────────────────┐ │ TIER SUPERVISEUR (Claude 3.5) │◄── (Appel API OpenRouter) │ - Audite la structure du PDF │ │ - Rédige la règle d'extraction │ └────────────┬──────────────────────┘ │ ▼ ┌───────────────────────────────────┐ │ GÉNÉRATION DE COMPÉTENCE │ │ Fichier SKILL_FOURNISSEUR.md │ └────────────┬──────────────────────┘ │ ▼ ┌───────────────────────────────────┐ │ INJECTION DANS LE RAG (Qdrant) │ │ Indexation dans `skills_catalog` │ └───────────────────────────────────┘

Conséquence Opérationnelle : À la prochaine réception d'une facture de ce même format, l'agent de base (Qwen 9B) interroge d'abord la collection skills_catalog dans Qdrant. Il y lit la consigne rédigée par le Superviseur, applique la logique, et traite le document localement avec 100% de fiabilité, sans nécessiter d'intervention humaine ni d'appel API payant.

PAGE 5 : WORKFLOWS MÉTIER CIBLES ET OBSERVABILITÉ

L'intégralité de la puissance de calcul est orientée vers trois objectifs précis visant à soulager la charge mentale du distributeur face à la comptabilité et à la logistique.

1. Les 3 Piliers Opérationnels

  1. Le Bouclier Anti-Comptable (Rapprochement des Achats) : Absorption automatisée des factures entrantes (ex: Paintcar, Corsica Ferries). Qwen extrait les montants, indexe le PDF dans Qdrant, et crée un Nœud Fournisseur + Facture dans Neo4j. À l'ingestion du relevé bancaire par n8n, le système tire automatiquement une flèche de paiement, justifiant immédiatement chaque ligne de débit.
  2. Désengorgement des Encaissements (LCR et Ventes) : Modélisation graphique des paiements de type Lettres de Change Relevé. Une seule bulle de mouvement bancaire de fin de mois projette des flèches de règlement vers de multiples factures clients simultanément.
  3. Réassort Intelligent (Le Pont Ventes/Achats) : Qwen analyse les lignes d'articles sur les factures de ventes sortantes, les regroupe par fournisseur d'origine, et utilise le MCP Hub pour générer un fichier Excel pré-rempli. Ce tableau constitue une proposition de reconstitution de stock, soumise à l'appréciation et à la validation finale du distributeur.

2. Le Second Écran (Tour de Contrôle Visuelle)

Pour superviser ces workflows complexes, le système impose une observabilité temps réel :

  • LangGraph Studio (React Flow) : Affiche la topologie de l'architecture. Lorsqu'une facture est traitée, le cheminement de la donnée s'illumine visuellement, permettant d'identifier immédiatement si une tâche est escaladée vers un modèle supérieur.
  • Langfuse V2 (Docker Port 3001) : Archive chirurgicalement les métadonnées : coût en jetons des agents, latence d'exécution des outils MCP, et capture intégrale des traces d'erreurs lors des rejets Pydantic pour faciliter l'audit.
